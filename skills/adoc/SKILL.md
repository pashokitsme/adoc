# adoc

CLI поверх недокументированный API autodoc.ru. Стоит как `adoc`, справка `adoc --help`, карта 214 эндпоинтов — `docs/autodoc-api.md` рядом со скиллом.

**Не лезь в autodoc.ru браузер.** Angular-SPA, не поднимается ни `ofetch`/obscura, ни Playwright: пустой `body`, вид «сайт мёртв». Данные только через `adoc`.

## Что вызывать

| Задача | Команда |
|---|---|
| Есть артикул → что это и почём | `adoc part <артикул>` |
| Карточка целиком: рейтинг, гистограмма, наличие | `adoc info <артикул> [brandId]` |
| Отзывы + выжимка нейросети | `adoc reviews <артикул> [brandId]` |
| Только название детали | `adoc search <текст>` → `adoc goods <categoryId>` |
| Предложения продавцов, сроки, аналоги | `adoc prices` / `adoc analogs` — **нужна авторизация** |
| Корзина, избранное, заказы, профиль | `adoc basket` / `favorites` / `orders` / `profile` — **нужна авторизация** |
| Машины юзера | `adoc garage` — **нужна авторизация** |
| Что подобрать под его машину | `adoc garage parts <carId>` — **нужна авторизация** |
| Эндпоинт без команды | `adoc get <путь> [k=v ...] [--auth]` |

Машине — `--json`, дальше `jq`. Без него таблица для человека; цвет гаснет сам при пайпе.

## Обязательный порядок: артикул → brandId

Один артикул = много производителей, цена/отзывы/наличие разные. `brandId` не обязателен: производитель один → тул подставит сам. Много → печатает список, выход код **2**. Не ошибка, а «уточни»: бери `ManufacturerId` из списка, повтори.

Коды: `0` — нашлось, `1` — ошибка или пусто, `2` — нужен `brandId`.

## Гараж

`adoc garage` — спрашивай первым, когда юзер говорит «моя машина» без модели: там марка, модель, модификация, год, VIN. Гадать не надо. `★` = основная машина. `adoc garage parts <id>` даёт подборку autodoc под модификацию — расходники, цены, сроки.

VIN и id машин — личные данные. Юзеру показывай, в сторонние запросы не тащи, не публикуй.

## Ловушки

1. **`adoc search` ищет категории и производителей, не товары.** Это подсказка. Товары на втором шаге: `adoc goods <categoryId>`. Полнотекстового поиска по товарам нет — текст в `find-goods` даст `totalCount: 0`, не баг.
2. **Оценки ≠ отзывы.** `info` даёт `4.91★ (56)`, `reviews` — «отзывов: 35». Оценка без текста в ленту не идёт. Не смешивай.
3. **401 = нужен `adoc login`.** Тело ошибки пустое, смотри текст тула, не JSON.
4. **Регистр параметров важен** в `adoc get`: почти везде PascalCase (`Article`, `ManufacturerId`, `PageNumber`), но поиск по артикулу — `article` со строчной. Сверяйся с `docs/autodoc-api.md`, не с интуицией.
5. **Артикул регистронезависим** — `n90954802` = `N90954802`.

## Авторизация — дело пользователя

Вход = пароль, вводит только человек: `adoc login` читает с терминала без эха. **Никогда не проси пароль в переписке и не суй в команду** — аргументом не принимается нарочно, чтоб не осел в истории шелла и в `ps`.

Нужна авторизация, токена нет → скажи юзеру запустить `adoc login` самому, жди. Проверка безопасна: `adoc whoami` печатает маскированные email/телефон и время жизни токена.

Токен — `~/.config/adoc/token.json`, права 600, обновляется сам. Не читай, не выводи.

## Когда API молчит

404 или поле пропало → autodoc поменял фронт. В `docs/autodoc-api.md` есть воспроизводимый способ снять карту заново: качай чанки Angular-бандла, грепай пути, методы, имена параметров. Надёжнее, чем гадать URL-ы.
