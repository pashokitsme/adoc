# adoc

CLI над недокументированным API autodoc.ru. Установлен как `adoc`, справка —
`adoc --help`, карта из 214 эндпоинтов — в `docs/autodoc-api.md` рядом со скиллом.

**Не пытайся открыть autodoc.ru браузером.** Это Angular-SPA, который не
поднимается ни в `ofetch`/obscura, ни в Playwright: страница отдаёт пустой
`body` и выглядит как «сайт не отвечает». Все данные берутся через `adoc`.

## Что вызывать

| Задача | Команда |
|---|---|
| Есть артикул, нужно «что это и почём» | `adoc part <артикул>` |
| Карточка целиком: рейтинг, гистограмма, наличие | `adoc info <артикул> [brandId]` |
| Отзывы и выжимка нейросети | `adoc reviews <артикул> [brandId]` |
| Только название детали | `adoc search <текст>` → `adoc goods <categoryId>` |
| Предложения продавцов, сроки, аналоги | `adoc prices` / `adoc analogs` — **нужна авторизация** |
| Корзина, избранное, заказы, профиль | `adoc basket` / `favorites` / `orders` / `profile` — **нужна авторизация** |
| Какие машины у пользователя | `adoc garage` — **нужна авторизация** |
| Что подобрать под его машину | `adoc garage parts <carId>` — **нужна авторизация** |
| Эндпоинт, под который нет команды | `adoc get <путь> [k=v ...] [--auth]` |

Для машинной обработки — `--json`, дальше `jq`. Без него вывод табличный и
человекочитаемый; цвета гаснут сами при пайпе.

## Обязательный порядок: артикул → brandId

Один артикул принадлежит нескольким производителям, и цена, отзывы и наличие у
них разные. `brandId` необязателен: если производитель один, тул подставит его
сам. Если их несколько — он напечатает список и выйдет с кодом **2**. Это не
ошибка, а требование уточнить: выбери `ManufacturerId` из списка и повтори.

Коды возврата: `0` — нашлось, `1` — ошибка или пусто, `2` — нужен `brandId`.

## Гараж

`adoc garage` — первое, что стоит спросить, когда пользователь говорит «моя
машина» и не называет модель: там уже есть марка, модель, модификация, год и
VIN, и гадать не нужно. `★` отмечает основную машину. `adoc garage parts <id>`
даёт подборку autodoc под эту модификацию — расходники с ценами и сроками.

VIN и id машин — личные данные пользователя. Показывай их ему, но не тащи в
сторонние запросы и не публикуй.

## Ловушки

1. **`adoc search` ищет не товары, а категории и производителей.** Это
   подсказка. Товары появляются на втором шаге, через `adoc goods <categoryId>`.
   Прямого полнотекстового поиска по товарам у autodoc нет — если попробовать
   искать текстом в `find-goods`, вернётся `totalCount: 0`, и это не баг.
2. **Число оценок ≠ число отзывов.** `info` показывает `4.91★ (56)`, а
   `reviews` — «отзывов: 35». Оценку ставят без текста, в ленту она не попадает.
   Не своди эти числа в одно.
3. **401 означает ровно одно — нужен `adoc login`.** Тело у ошибки пустое, так
   что ориентируйся на текст самого тула, а не на JSON.
4. **Регистр параметров значим** при работе через `adoc get`: почти везде
   PascalCase (`Article`, `ManufacturerId`, `PageNumber`), но у поиска по
   артикулу параметр называется `article` со строчной. Сверяйся с
   `docs/autodoc-api.md`, а не с интуицией.
5. **Артикул регистронезависим** — `n90954802` и `N90954802` одно и то же.

## Авторизация — дело пользователя

Вход требует пароля, и вводит его только человек: `adoc login` читает пароль с
терминала без эха. **Никогда не проси пароль в переписке и не подставляй его в
команду** — аргументом он не принимается намеренно, чтобы не осесть в истории
шелла и в `ps`.

Если команда требует авторизации, а токена нет, скажи пользователю запустить
`adoc login` самому и дождись. Проверить состояние можно безопасно:
`adoc whoami` печатает маскированные email и телефон и время жизни токена.

Токен лежит в `~/.config/adoc/token.json` с правами 600 и обновляется сам.
Не читай этот файл и не выводи его содержимое.

## Когда API молчит

Если эндпоинт вдруг отвечает 404 или поле пропало — autodoc поменял фронт.
В `docs/autodoc-api.md` описан воспроизводимый способ снять карту заново:
скачать чанки Angular-бандла и выгрепать из них пути, методы и имена
параметров. Это надёжнее, чем угадывать URL-ы.
