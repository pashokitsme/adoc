# adoc

CLI-агрегатор магазинов запчастей: одна команда → все сайты сразу. Бинарь `adoc`,
справка `adoc --help`, сайты `adoc providers`. Подключены autodoc.ru и armtek.ru;
карты API — `docs/autodoc-api.md`, `docs/armtek-api.md` в репо `adoc` (каталог
`docs/`; скилл их не копирует).

**Браузером на сайты не лезь.** Оба Angular-SPA: ни `ofetch`/obscura, ни
Playwright — пустой `body`, «сайт мёртв». Данные только через `adoc`.

## Что вызывать

| Задача | Команда |
|---|---|
| Артикул → цены, сроки, наличие везде | `adoc part <артикул> [бренд]` |
| То же + аналоги | `adoc part <артикул> [бренд] --analogs` |
| Только аналоги, таблицей | `adoc analogs <артикул> [бренд]` |
| Карточка: склады, гистограмма, ссылка | `adoc info <артикул> [бренд]` |
| Один сайт | `adoc part <артикул> --only autodoc` |
| Название → артикулы | `adoc search <текст>` |
| То же, не под машину гаража | `adoc search <текст> --no-car` · `--car <id>` |
| Отзывы, оценки | `adoc reviews <артикул> [бренд]` |
| Корзины всех сайтов | `adoc basket` |
| Положить строку выдачи `part`/`analogs` | `adoc basket add <#> [--qty <n>]` |
| Убрать / изменить | `adoc basket rm <сайт> <ID>` · `adoc basket set <сайт> <ID> --qty <n>` |
| Заказы | `adoc orders` |
| Машины | `adoc garage` |
| Кто авторизован | `adoc accounts` (= `adoc whoami`) |
| Сайты и их умения | `adoc providers` |
| Все команды и флаги | `adoc --help` (= `adoc help`) |
| Команда конкретного сайта | `adoc <сайт> <команда> …` |

Ссылки есть в каждой выдаче: под таблицей списком `<#>  <адрес>`, номер = строка
таблицы (`part`, `analogs`, `search`, «уточни бренд», корзина); отдельной строкой
у заголовка, где страница одна на блок (`info`, `reviews`, `orders`, корзина).
Одинаковый адрес дважды не печатается — десяток предложений, карточка одна.
Строка сразу на нескольких сайтах отдаёт остальные адреса в блок «ещё ссылки» под
таблицей, рядом с номером — сайт. В `--json` это поле `url`, у склеенных строк
`search` и брендов ещё `urls` (сайт → адрес). Показывай их: пользователь идёт по
ним на сайт.

`ADOC_LINKS`=`osc8` вшивает адрес терминальной ссылкой в текст строки — номер,
артикул, название, имя сайта (списка под таблицей тогда нет), `list` — список,
`off` — без адресов; в пайпе сам по себе `list`, так что агент всегда видит
голый адрес. В `osc8` под выводом стоит строка «ссылки — Cmd+клик …»: она про
терминал человека, пересказывать её не надо.

Строка «показано X из Y» — про склейку обёртки; если сайты сказали общее число,
добавит «а всего у сайтов Z». Y — что в руках, Z — что есть на сайтах, дальше
`--page`.

Машине `--json`: ровно один JSON-объект в stdout, дальше `jq`. Без него таблица
для человека; цвет гаснет при пайпе. Ошибка в `--json` — тело
`{"error":{"code":"…","message":"…"}}`, без `--json` — текст в stderr.

Выбор сайтов: `--only a,b` (= `--providers`), `--skip a,b`; неизвестный сайт →
`bad_args` со списком известных.

Флаг со значением: `--flag value` или `--flag=value`, значение обязательно:
`--limit --json` = `bad_args`, не лимит «--json». Переключатель значения не
берёт: `--json=true` = `--json`, `--json=false` = флага нет.

## Обязательный порядок: артикул → бренд

Один артикул = много производителей, цена/отзывы/наличие разные. `adoc part` сам
делает первый шаг: спрашивает сайты, кто выпускает артикул.

Брендов несколько → код **2**, тело `{"error":{"code":"ambiguous","items":[…]}}`,
у каждого варианта в `extra.providers` — сайты, где он есть. Это не ошибка, а
«уточни»: бери бренд из `items`, повтори `adoc part <артикул> <бренд>`. Названный
бренд не нашёлся → код **1**, `{"error":{"code":"notfound","items":[…]}}` с теми
же `items` — проверь написание по списку.

Коды: `0` — нашлось (пустой список тоже `0`), `2` — уточни бренд, `1` — прочее.

## Частичный отказ — это не провал

Сайт с ошибкой → жёлтая строка в stderr и поле `errors` в `--json`; остальные
печатаются как обычно, код возврата `0`. Смотри, что пришло, не только stderr.
Exit `1` при агрегации = «не ответил никто из спрошенных».

Строка `armtek: нужен вход — adoc login armtek` значит ровно это: аккаунта нет.
Остальные сайты в этой выдаче рабочие.

## Корзина

`adoc basket` — корзины всех сайтов блоками, итог по каждому и общий. Колонка `#`
— номер строки, `ID` — идентификатор позиции, его и передавай в
`basket set`/`basket rm` вместе с именем сайта. Если `ID` начинается с дефиса или
похож на подкоманду — флаг: `adoc basket rm <сайт> --id <ID>`.

`adoc basket add <#>` берёт строку последней выдачи `adoc part`/`adoc analogs`
(живёт сутки в `~/.config/adoc/last-part.json`). Кэш переписывает каждая
удавшаяся `part`/`analogs`, включая пустую: после неё номеров нет вообще.
Уцелеет только после неудачи, когда шаг предложений не ответил ни у кого.
Номер годен для той выдачи, что ты только что видел: кэш протух или обнулился —
команда попросит повторить `part`, номера не выдумывай.
Для скриптов точная форма: `adoc basket add <сайт> --ref <json>`, где `ref` —
объект из `adoc part --json`, скопированный **как есть**.

## Гараж

`adoc garage` — спрашивай первым на «моя машина» без модели: там марка, модель,
модификация, год, VIN. Не гадай. `★` — основная машина. Гараж локальный,
`~/.config/adoc/garage.json`, не на сайтах, никуда не отправляется.

`adoc search` по умолчанию ищет под **основную** машину: сайту уходит только его
собственный `ref` этой машины из `garage import` — не VIN и не гараж целиком. Над
таблицей написано, какая машина участвовала и у каких сайтов. Сайту без своей
привязки достаётся TecDoc-идентификатор модификации из чужой (`modificationId` у
autodoc = `linkingTargetId` у armtek), в заголовке помечено «(через <сайт>)»;
совсем без привязки сайт ищет по всему каталогу и говорит жёлтой строкой. Другая
машина — `--car <id>`, без машины — `--no-car`. Выдача странно узкая/широкая —
смотри именно эту строку.

`adoc garage import <сайт>` забирает машины одного сайта и сливает: сначала по
VIN, при несовпадении — со своей машиной **без VIN** той же марки, модели, года.
Год участвует: машина, заведённая руками без `--year`, с машиной сайта, где год
есть, не сольётся — придёт вторая строка. Хочешь слияния — впиши год или VIN до
импорта.

VIN и id машин — личные данные. Пользователю показывай, в сторонние запросы не
тащи, не публикуй.

## Авторизация — дело пользователя

Вход = пароль, вводит только человек: `adoc login <сайт>` читает с терминала без
эха. **Пароль в переписке не проси, в команду не суй** — аргументом не
принимается нарочно, чтоб не осел в истории шелла и в `ps`.

Нужен вход, аккаунта нет → скажи пользователю запустить `adoc login <сайт>`, жди.
Проверка безопасна: `adoc accounts` печатает по строке на сайт
(`adoc accounts <сайт>` — про один). `ok:true` — аккаунт есть, токен рабочий;
`ok:false` — входа нет или токен протух, лечится тем же `login`. Email и телефон
— **как есть, без маскировки**, это личные данные: показал и забыл, наружу не
отправляй.

Файлы аккаунтов — `~/.config/adoc/accounts/<сайт>.json`, права 600. **Не читай и
не печатай**: там токены. Потому же не запускай `adoc <сайт>
login --json` — он печатает токены в stdout; обёртка `adoc login` их не печатает
никогда.

## Ловушки

1. **`search` у autodoc отдаёт товары первой подходящей категории, а не всё
   подряд.** Прочие категории — в `extra.categories`; по ним ходи
   `adoc autodoc goods <categoryId>`. Полнотекстового поиска по товарам нет —
   текст в `find-goods` даст `totalCount: 0`, это не баг.
2. **Оценки ≠ отзывы.** `4.91★ (56)` — оценки, «отзывов: 35» — тексты. Оценка без
   текста в ленту не идёт. Не смешивай.
3. **У armtek цена, срок, наличие зависят от точки выдачи.** Текущую покажет
   `adoc armtek vstel`; без входа она московская.
4. **`describe` помечает `offers` как `auth: false`, но autodoc без токена всё
   равно отдаёт `auth`.** Верь коду ошибки, не полю `auth`.
5. **Регистр параметров важен** в `adoc autodoc get`: почти везде PascalCase
   (`Article`, `ManufacturerId`, `PageNumber`), но поиск по артикулу — `article`
   со строчной. Сверяйся с `docs/autodoc-api.md`, не с интуицией.
6. **Артикул регистронезависим** — `n90954802` = `N90954802`, пробелы и дефисы
   не важны, и у обёртки, и у сайтов.
7. **armtek держит темп.** Команды подряд ловят 429 с капчей: обычный отказ
   одного сайта (`http`, exit 0, остальные показаны). Подожди пару минут, в цикле
   не повторяй.

## Свои команды сайтов

`adoc <сайт> <команда>` пробрасывается сайту как есть, вместе с `--help`.

- **autodoc**: `goods <categoryId>`, `prices`, `favorites`, `profile`,
  `garage [parts|main]`, `get <путь>`, `post <путь>`. Эндпоинт без команды —
  через `get`/`post`.
- **armtek**: `vstel [поиск]`, `raw <METHOD> <путь>` (умеет писать, нужен вход).

`info`, `analogs`, `orders` — команды контракта: одинаковы у всех сайтов, звать
обёрткой (`adoc info …`), не через конкретный сайт.

## Когда API молчит

404 или поле пропало → сайт поменял фронт. В `docs/autodoc-api.md` и
`docs/armtek-api.md` есть воспроизводимый способ снять карту заново: качай чанки
Angular-бандла, грепай пути, методы, имена параметров. Надёжнее, чем гадать URL-ы.
