# Заметки агрегатора (v2)

Живой блокнот ветки `feat/aggregator`. Личных данных здесь нет и быть не должно:
ни артикулов из чужих корзин, ни VIN, ни почты, ни токенов.

## Что делаем

Требования владельца (сжато):

1. **Ссылки везде**, где сайт их отдаёт: `search`, `reviews`, `basket`, `part`
   (предложения и «где»), `info`. В `--json` они и так лежат в объектах.
2. **`search` с учётом гаража**: по умолчанию — главная машина локального
   гаража, каждому провайдеру уходит его `refs[<provider>]`; `--car <id>` —
   другая машина, `--no-car` — без машины.
3. **Новые команды контракта**: `info`, `analogs`, `orders`.
4. **UX-проход** по выводу всех команд обёртки — на фейках, а после мержа
   `feat/providers-v2` и на настоящих сайтах.

Контракт-дельта, под которую пишем: `scratchpad/contract-delta.md`
(имена обязательны, вторая сторона делает то же в `src/sdk/**`).

## Решения по вёрстке

**До мержа** ссылки печатались списком под таблицей (`linkList`). **После
мержа** их печатает рендер SDK: колонка `ССЫЛКА` в таблицах и строка у
карточки, заказа и отзывов. Две системы разом дали бы каждый адрес дважды,
поэтому свой список снят, а от него остались:

- `extraLinks()` — только адреса, которых в таблице нет: у склеенной строки
  `search` или «уточни бренд» сайтов два, а колонка одна. Блок «ещё ссылки»
  под таблицей, номер слева тот же, что в колонке `#`.
- `numCol()` — колонка `#` там, где рендер SDK её не рисует (поиск, бренды):
  блоку «ещё ссылки» надо на что-то ссылаться.
- `blockTitle()` — имя сайта над блоком (`info`, `reviews`, `orders`,
  корзина). Адрес страницы в него больше не вписывается: его печатает SDK.

`MergedProduct` и `MergedBrand` держат `url` (первый, кто его дал — он и
уезжает в колонку) и `urls` (сайт → адрес, для блока «ещё ссылки»).

## Мерж `feat/providers-v2` (сделан)

`src/core/delta.ts` удалён, импорты переведены на `../sdk/index.ts`,
приведения `as Cap` сняты — `Capability` из контракта теперь знает `orders`.
Конфликты были в `validate.ts` (списки capability) и в фейковом провайдере:
у обеих сторон появились `info`/`analogs`/`orders`, взяты контрактные методы
ветки провайдеров, к ним добавлены наши ссылки, `--car` и кнопки
`FAIL_INFO`/`FAIL_ANALOGS`/`FAIL_ORDERS`/`NOCAR`/`EMPTY_SEARCH`.
Карточку и заказы рисует SDK (`renderInfo`, `renderOrders`), свои `infoCard`
и `ordersTable` удалены.

## Проверка на настоящих сайтах (после мержа)

Оба аккаунта, только чтение; корзина — циклами «положить → увидеть → убрать».
Заказы, оформление и профиль не трогались. Обе корзины были пусты до проверки
и оставлены пустыми. Гараж не пострадал: `garage import autodoc` только
дополнил ref машины полями `brandName` и `modelId`, `garage import armtek` —
«добавлено 0, обновлено 0» (на armtek гараж пуст).

Что прогонялось: `providers`, `accounts`, `part <артикул>` (несколько брендов
→ таблица вариантов, код 2), `part <артикул> bosch`, `search "фильтр масляный"`
с машиной и с `--no-car`, `info`, `analogs`, `reviews`, `orders`, `basket`
(add → basket → rm на обоих сайтах), `garage`, `garage import autodoc`,
`garage import armtek`, проброс `autodoc prices` и `autodoc info`,
`armtek --help`.

**Что поправлено по итогам (было → стало):**

1. `analogs`: в таблице была колонка с пометкой «аналог» у каждой строки —
   заголовок таблицы и так говорит «аналоги». Пометка снята из вывода,
   в `--json` осталась.
2. `garage`: подсказка шла вплотную к таблице → отделена пустой строкой, как
   у всех остальных команд.
3. `search`: сайт, ответивший пустым списком, молча исчезал из выдачи (у
   armtek без машины это обычное дело) → теперь назван строкой
   «ничего не нашли: <сайт>». В `errors` его по-прежнему нет: это не отказ.
4. Ссылки: своя система списков снята в пользу колонки `ССЫЛКА` из SDK
   (см. «Решения по вёрстке»), README и скилл переписаны под неё.

**Что осталось некрасивым и почему не тронуто:**

- Строка таблицы с адресом получается длинной: у `part` без ссылок она 129
  знаков, с адресом armtek — 238; у `search` адрес свой почти у каждой строки,
  и строки идут по 165–230 знаков. В терминале уже 120 знаков это перенос.
  Таблицы рисует SDK — решение о колонке за веткой провайдеров.
- `info` у armtek показывает склад кодом (`MOV0000019`): у склада нет имени.
- Название позиции корзины у armtek приезжает сырым (`фильтр масляный!\ Mazda
  626, Mit…`).
- Свободный поиск armtek без машины отдаёт малорелевантную выдачу одного
  бренда (кольца и прокладки на запрос «фильтр масляный»).

## Что предполагалось о выводе провайдеров — подтверждено мержем


1. **`info`** отвечает `{"info": {...}}` (объект в поле `info`, не голая
   карточка). Обязательны только `article` и `brand`; всё прочее
   необязательно, `rating.histogram` — от 5★ к 1★, `stock[]` c полем `code`.
2. **`analogs`** отвечает `OffersResult` и помечает строки `analog: true`.
   Агрегатор всё равно перепроверяет по артикулу и точные строки в таблицу
   аналогов не пускает — если провайдер вернёт точное совпадение, оно просто
   исчезнет из выдачи `adoc analogs`.
3. **`orders`** отвечает `{"items": [Order]}`; `date` — ISO, из него берутся
   первые 10 символов. Заказ без `items` рисуется прочерком в колонке
   ПОЗИЦИЙ. Capability называется ровно `orders`.
4. **`--car <json>`** уходит сайту как одна строка `JSON.stringify(ref)`.
   Провайдер обязан принимать её флагом со значением (то есть `car` должен
   попасть в `CONTRACT_VALUE_FLAGS`), а при неумении — предупредить и искать
   без машины.
5. **Ссылки**: `Product.url`, `Offer.url`, `BrandHit.url`, `Reviews.url`,
   `Review.url`, `BasketItem.url`, `Info.url`, `Order.url`, `OrderItem.url`.
   Абсолютные, с протоколом: агрегатор печатает их как есть.
6. **README/SKILL уже описывают состояние после мержа**: `info`, `analogs` и
   `orders` вынуты из таблиц «свои команды сайта» у autodoc и armtek. Если
   ветка провайдеров это не привезёт — вернуть строки обратно.

Все шесть пунктов подтвердились, кроме одного уточнения: `info` у обоих
сайтов отдаёт `stock` без `quantity` там, где сайт остатка не знает, и
рендер SDK показывает в этом случае «нет».

## Открытые вопросы

- Ширина таблиц со ссылками (см. выше) — за веткой провайдеров.
- «из Y» под таблицей `analogs` считает склеенную страницу, а не весь каталог
  сайта: armtek честно предупреждает, что аналогов 575 на 16 страницах, а
  строка внизу говорит «показано 5 из 43».
