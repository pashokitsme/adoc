# adoc

Расширяемый CLI-инструмент для взаимодействия с сайтами для заказа автозапчастей, а также неофициальные API-обёртки над [autodoc.ru](https://autodoc.ru) и [armtek.ru](https://armtek.ru).

Как расширить? – См. [интерфейс провайдера](docs/contract.md).

```console
$ adoc part n90954802
n90954802 · VAG · armtek, autodoc

#  ПРОВАЙДЕР  БРЕНД  НАЗВАНИЕ  ЦЕНА   НАЛИЧИЕ  СРОК    ПРОДАВЕЦ  РЕЙТИНГ
1  armtek     VAG    Болт      380 ₽  3 шт     2 дня   armtek    4.5★ (10)
2  autodoc    VAG    Болт      407 ₽  12 шт    1 день  Москва    4.9★ (56)
```
Вся полученная информация может быть неточной, неполной и
устаревшей — см. [docs/autodoc-api.md](docs/autodoc-api.md),
[docs/armtek-api.md](docs/armtek-api.md).

## Ссылки

Адрес страницы печатается везде, где сайт его даёт. В терминале, который умеет
терминальные ссылки (OSC 8), он вшит в саму строку — кликаются номер, артикул,
название и имя сайта, — а последней строкой вывода идёт подсказка «ссылки —
Cmd+клик (iTerm2, WezTerm, ghostty) или Ctrl+клик (kitty, VS Code, Windows
Terminal)»: вшитая ссылка ничем не помечена, и без подсказки таблица читается
как обычный текст. Иначе (труба, незнакомый терминал) адреса идут списком под
таблицей, номер слева — тот же, что в колонке `#`. Режим переключает
[`ADOC_LINKS`](#переменные-окружения).

## Установка

```sh
$ bun install -g github:pashokitsme/adoc
$ gh skill install pashokitsme/adoc adoc
```

Ставятся три бинаря: `adoc` — обёртка, `adoc-autodoc` и `adoc-armtek` —
провайдеры. Обычно нужен только первый.

## Порядок: артикул → бренд

Один артикул выпускают разные производители, и цена, срок и отзывы у них
разные. `adoc part <артикул>` сначала спрашивает у всех сайтов список брендов,
и если бренд не один — печатает таблицу вариантов с колонкой «ГДЕ» и выходит с
кодом `2`. Повторите с брендом: `adoc part n90954802 VAG`.

## Несколько артикулов за раз

`adoc part 815010730,900355,31485` спрашивает каждый артикул по очереди и
печатает раздел на каждый: заголовок, своя таблица, свои ссылки. Список из
файла — `adoc part --file list.txt`, где строка это «артикул [бренд]», а `#`
начинает комментарий. Бренд, названный в команде, относится ко всем артикулам;
бренд из файла сильнее — он стоит рядом со своим артикулом. То же самое умеет
`adoc analogs`.

Артикулы идут по очереди, а сайты внутри артикула — параллельно: сайты
ограничивают темп по аккаунту, и веер из десяти артикулов положил бы выдачу.

Неоднозначный бренд не обрывает список: его раздел показывает варианты, а
остальные артикулы отвечают как обычно. Код `2` — только когда уточнять надо у
всех. В `--json` список приходит как `{items: [...], errors: [...]}`.

Кэш строк для `basket add <#>` пишет **последний удавшийся** артикул списка —
о том, чьи это номера, сказано под выдачей.

## Подойдёт ли машине

`adoc fits <артикул> [бренд]` спрашивает сайты про машину гаража и печатает по
строке на сайт: **подходит**, **не подходит** или **не знает**. Третий ответ —
полноценный: сайт, у которого нет данных о применимости этой детали к этой
модификации, так и говорит, а выдуманное «не подходит» стоило бы покупателю
детали. Сайту уходит только его собственный ref машины (`garage import`), не
VIN и не гараж. Машину выбирают `--car <id>`, по умолчанию основная.

## Аналоги: по номеру и по функции

`adoc analogs` (и `part --analogs`) показывает **замены по номеру**: тот же
узел под другим номером — кросс-ссылки сайтов. Деталь той же функции другого
производителя по номеру не ищется вовсе: для неё есть `adoc search "<название
детали>"` под машиной гаража. Под коротким списком аналогов это написано и в
самой выдаче.

## Сколько строк на самом деле

Под таблицей стоит подпись, и только когда есть о чём говорить: «показано X из
Y» — обрезал `--limit`; «показано X, всего у сайтов Y» — сайт нашёл больше, чем
поместилось на его страницу (у armtek на один артикул бывает 575 аналогов, а
страница отдаёт 43). Всё показанное подписи не получает.

`--page <n>` листает выдачу сайтов, `--limit <n>` расширяет страницу. Страница
за концом выдачи не притворяется пустым результатом: `search … --page 9`
скажет «страница 9 пуста: всего 20, страница 1 с --limit 30 показывает всё».

## Как это устроено

`adoc` — инструмент, который работает с конкретными сервисами, подключаются при помощи API-обёрток — отдельный программ, которые реализуют [интерфейс провайдера](docs/contract.md). Обёртка находит их сама:
встроенные лежат в `src/providers/*/main.ts`, чужие — это любые исполняемые
файлы `adoc-<id>` в `PATH`.

Авторизация требуется в каждом сервисе отдельно: `adoc login <provider>` запускает диалог в терминале, токены сохраняются в `~/.config/adoc/accounts/<id>.json`. При помощи `adoc providers` можно узнать, какие сервисы подключены и что умеют.

Учётные данные хранятся в `~/.config/adoc/accounts/<id>.json`. Директория может переопределяется при помощи `$ADOC_CONFIG_DIR` — он и остальные переменные в разделе [Переменные окружения](#переменные-окружения).

## Корзина

Своей корзины у обёртки нет: каждая позиция лежит в корзине своего сайта,
`adoc basket` показывает их блоками, с итогом по каждому и общим внизу.
Колонка `#` — порядковый номер строки, колонка `ID` — идентификатор позиции у
сайта; в `basket set` и `basket rm` передаётся именно `ID`, вместе с именем
сайта. Позиционным аргументом его набирают руками, а флагом `--id <id>` — когда
он начинается с дефиса или похож на подкоманду: у autodoc он длинный и
склеенный.

`adoc basket add <#>` берёт строку из `last-part.json`. Этот кэш переписывает
каждая удавшаяся `part` — в том числе та, что ничего не нашла: она обнуляет
список строк, чтобы `basket add 1` сказал «строк нет», а не положил в корзину
строку прошлого артикула. Не тронет кэш только неудача: если шаг `offers` не
ответил ни у кого, вчерашние строки остаются на месте.

## Гараж

Список добавленных автомобилей локальный, хранится в `~/.config/adoc/garage.json`.

`adoc search` по умолчанию ищет **под основную машину гаража**: «фильтр
масляный» без машины — это тысячи строк, а с ней — те, что подходят. Сайту
уходит не VIN и не гараж, а только его собственный идентификатор этой машины —
`refs[<сайт>]`, тот самый `ref`, который положил туда `garage import` этого же
сайта. Какая машина участвовала и у каких сайтов — написано над таблицей.
`--car <id>` берёт другую машину гаража, `--no-car` выключает подбор совсем.

Привязку хватает и одну на всех: идентификатор модификации TecDoc у autodoc
зовётся `modificationId`, у armtek — `linkingTargetId`, и это одно и то же
число. 

`adoc garage import <provider>` забирает машины с одного названного сервиса.

## Авторизация

```sh
$ adoc login autodoc      # диалог в терминале, пароль без эха
$ adoc accounts           # кто авторизован у всех сайтов сразу
$ adoc logout autodoc     # забыть аккаунт
```

Пароль вводится только с терминала и на диск не пишется. `adoc login` не
печатает токены никогда; а вот у провайдера напрямую — `adoc autodoc login
--json` — в stdout уходит сохранённый аккаунт целиком, вместе с токенами:
этот вывод нельзя ни логировать, ни пересылать.

Колонка «СТАТУС» в `accounts` — это поле `ok` из `whoami` провайдера; что
именно он им отвечает и когда переписывает файл аккаунта, сказано в
[контракте](docs/contract.md).

Имя, email и телефон обёртка показывает **как есть, без маскировки** — это
личные данные владельца аккаунта, он их и видит.

## Переменные окружения

| переменная | кто читает | что делает | по умолчанию |
|---|---|---|---|
| `ADOC_CONFIG_DIR` | обёртка и все провайдеры | каталог настроек: гараж, кэш последней выдачи `part`, файлы аккаунтов | `$XDG_CONFIG_HOME/adoc`, а без него — `~/.config/adoc` |
| `ADOC_PROVIDERS_DIR` | обёртка | берёт провайдеров только из этого каталога (подкаталог с `main.ts` на провайдера), заменяя и встроенные, и найденные в `PATH` | встроенные + `adoc-<id>` из `PATH` |
| `ADOC_LINKS` | вывод для человека | `osc8` — адреса терминальными ссылками в тексте, `list` — списком под таблицей, `off` — не показывать; см. [Ссылки](#ссылки) | `osc8` в TTY знакомого терминала, иначе `list` |
| `NO_COLOR` | вывод для человека | гасит цвет; на ссылки не влияет | цвет включён в TTY |
| `ADOC_NO_WARN` | обёртка и все провайдеры | гасит предупреждения (то же самое на один вызов — `--quiet`, кратко `-q`): жёлтые строки отказов, заметки сайтов, подсказку про клик. Ошибки, выдача и код возврата те же | предупреждения печатаются |
| `ARMTEK_PHONE`, `ARMTEK_PASSWORD` | провайдер armtek | учётка для `adoc armtek login` без терминала; нужны обе | вход спрашивает человека |

`PATH` и `XDG_CONFIG_HOME` — общесистемные, но обёртка смотрит и в них: в
первом ищет провайдеров `adoc-<id>`, во втором — каталог настроек.

Только для тестов, в обычной работе не нужны:

| переменная | что делает |
|---|---|
| `ADOC_FIXTURES` | провайдер autodoc читает записанные ответы из этого каталога вместо сети |
| `ADOC_AUTODOC_BASE` | адрес API autodoc; принимается только localhost |
| `ADOC_TIMEOUT_MS` | таймаут HTTP-запроса провайдера autodoc, мс |
| `ARMTEK_FIXTURES` | маршруты фикстур для `test/fixtures/armtek-cli.ts`: JSON «кусок пути → файл» |
| `FAKE_<ID>_*`, `NOISY_STDERR_BYTES` | ручки фиктивных провайдеров из `test/fixtures`: задержка, отказ нужным кодом, пустая выдача, отсутствие capability, мусор в stderr |

## Разработка

```sh
$ bun test
$ bun run typecheck
```

Тесты не ходят в сеть и не трогают настоящий конфиг: `ADOC_CONFIG_DIR` уводит
конфиг во временный каталог, `ADOC_PROVIDERS_DIR` подменяет весь набор
провайдеров фикстурами из `test/fixtures/providers`, а провайдеры читают
записанные ответы вместо сети — autodoc через `ADOC_FIXTURES`, armtek через
подменённый транспорт (`test/fixtures/armtek-cli.ts`). Все переменные —
в разделе [Переменные окружения](#переменные-окружения).

```sh
$ ADOC_FIXTURES=test/fixtures/autodoc/http adoc autodoc info n90954802
```

Имя файла фикстуры — метод и путь запроса, где `/` заменены на `_`:
`GET /api/goods-service/goods/info` → `GET__api_goods-service_goods_info.json`.
